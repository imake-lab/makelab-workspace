# makelab-workspace

**一个文件夹，多个 AI 共用：同一份规则，同一套技能和工具，同一份记忆。**

适用于 WorkBuddy、Codex、Claude Code、OpenCode、Pi，以及其他支持 `AGENTS.md` 的智能体。

> 工具可以换，规则和记忆要放在自己手里。

**部署只要发一段话**：把 [安装方式](#安装方式) 里的提示词发给你的智能体，它会按 [`INSTALL.md`](INSTALL.md) 把工作空间装好、问你几个问题填好、跑完自检交给你。

## 这个仓库能做什么

1. **一份规则，多个 AI 共用**：所有智能体读同一个 `AGENTS.md`，Claude Code 通过 `CLAUDE.md` 一行引入。
2. **技能和工具共用**：放在根目录 `skills/`、`tools/`，靠索引匹配，新增一个，所有智能体同时能用。
3. **记忆只有一份**：`memory/MEMORY.md` 是唯一记忆源，换工具不丢；各工具自带的记忆只当临时缓存。
4. **记忆先确认再写**：`save-memory` 技能先出草稿，你确认了才落盘；被推翻的结论留档，防止绕回去。
5. **启动三层加载**：必读的先读，项目约定确定任务后读，技能和工具用到才读，上下文不会一次撑满。
6. **启动自检**：`check-workspace` 脚本一次查完必需文件、多余规则文件、索引、记忆格式和疑似密钥。
7. **发链接就能部署**：`INSTALL.md` 是写给智能体的部署说明，发一段提示词，智能体照着装好、填好、自检完再交给你。

## 包含什么

### `AGENTS.md`：唯一规则入口

- 工作空间用途、目录、三层加载、冲突优先级、多智能体共用规矩、记忆规则、权限、凭据、错误处理、完成汇报格式。
- 必需文件清单写在 `<!-- check:required -->` 标记里，规则和自检脚本用同一份清单。
- 方括号【】是要换成你自己内容的地方。

### `INSTALL.md`：给智能体的部署说明

- 读者是智能体：问目录和用途 → 检查目录 → 拉取文件 → 填写个人内容 → 自检 → 交接。
- 目标目录不为空时先停下问你；同名文件不覆盖，已有的 `AGENTS.md` 先给合并方案再改。
- 写明不做的事：不碰凭据、不改目标目录以外的文件和工具全局配置、不装系统软件、不上传任何内容。

### `CLAUDE.md`：Claude Code 入口

- 单独一行 `@AGENTS.md`，把主规则整份引入。
- 只放 Claude Code 专属说明，不重复任何规则。

### `identity/ME.md`：我是谁

- 红线、身份、偏好、雷区。只有你本人能改。

### `memory/MEMORY.md`：唯一记忆源

- 按主题分节，每条一句，句末带日期，最后一节是「已推翻」。

### `skills/save-memory`：记忆草稿与确认写入

- 从对话里挑出拍板的决定、给出的数据、否决的方案，出草稿，收到明确确认才写入。
- 详见 [`skills/save-memory/SKILL.md`](skills/save-memory/SKILL.md)。

### `tools/check-workspace`：结构自检

- 只读，Python 标准库，附 22 个单元测试。
- 详见 [`tools/check-workspace/README.md`](tools/check-workspace/README.md)。

### `projects/`、`outputs/`

- `projects/<项目>/README.md` 写单个项目的约定，确定任务后才读；附一个示例项目。
- `outputs/` 放成品，按 `<主题>-YYYY-MM-DD/` 建目录。

## 目录结构

```text
makelab-workspace/
├── AGENTS.md           唯一规则入口
├── CLAUDE.md           Claude Code 入口：@AGENTS.md + 专属说明
├── INSTALL.md          给智能体的部署说明
├── identity/ME.md      我是谁、红线、偏好
├── memory/MEMORY.md    唯一记忆源
├── skills/             共用技能：README.md 索引 + 每个技能一个目录
│   └── save-memory/
├── tools/              共用工具：README.md 索引 + 每个工具一个目录
│   └── check-workspace/
├── projects/           项目约定，按需读取
│   └── example/
└── outputs/            成品
```

## 环境要求

- 至少一个支持 `AGENTS.md` 的智能体，或 Claude Code。
- 自检脚本：Python 3.8 及以上，不用装依赖。

## 安装方式

### 让智能体帮你部署（推荐）

把下面这段话原样发给任意一个能上网、能操作文件的智能体，把尖括号里的目录换成你自己的：

```text
帮我部署 makelab-workspace 工作空间。
1. 先完整读这份部署说明：https://raw.githubusercontent.com/imake-lab/makelab-workspace/main/INSTALL.md
2. 严格按说明一步一步执行，部署到：<目录，例如 ~/workspace>
3. 任何会覆盖或删除我已有文件的操作，先问我。
4. 部署完把自检结果原样给我看。
```

智能体上不了网时，先自己下载 [ZIP](https://github.com/imake-lab/makelab-workspace/archive/refs/heads/main.zip) 解压，再发这段：

```text
我把 makelab-workspace 解压到了 <目录>。
请完整读其中的 INSTALL.md，从第 3 步开始执行；任何会覆盖或删除文件的操作先问我，最后把自检结果原样给我看。
```

部署说明写在 [`INSTALL.md`](INSTALL.md)，发之前可以先看一遍它会让智能体做什么。

### 手动安装

```bash
git clone https://github.com/imake-lab/makelab-workspace.git
cd makelab-workspace
```

也可以直接下载 ZIP 解压。整个文件夹就是你的工作空间根目录，不用装进任何工具的配置目录。装好后按下面的「3 分钟快速上手」填写。

## 3 分钟快速上手

1. 改 `identity/ME.md` 和 `AGENTS.md` 里的【】。
2. 删掉 `memory/MEMORY.md` 里的示例条目和 `projects/example/`，更新 `projects/README.md`。
3. 运行自检：

   ```bash
   python3 tools/check-workspace/check.py
   ```

4. 用任意一个智能体打开**根目录**，第一句话让它按 `AGENTS.md` 第 2 节自检，并复述一遍读了哪些文件。复述得出来，说明规则已经读到了。
5. 加技能：建 `skills/<名字>/SKILL.md`，在 `skills/README.md` 登记一行；加工具同理。再跑一次自检。

## 日常怎么用

装好只是骨架：模板里只有 1 个技能、1 个工具。要达到「换哪个 AI 都一样干活」的效果，靠的是下面这些习惯，以及你按同样的方法一点点攒起来的技能和工具。

### 每次开工

- 永远从**根目录**打开智能体，不要在子目录里启动：所有路径都是相对根目录写的，在子目录启动，路径和索引全都对不上。
- 第一句话说清楚做哪个项目、做什么，例如：

  ```text
  当前项目：example。今天汇总本周周报。
  ```

- 智能体应该先用一句话报告：读了哪些文件、自检结果、准备做什么。没报告，就提醒它「先按 AGENTS.md 第 2 节自检」。
- 没说做哪个项目时，规则要求它先问你，不自己猜。

### 一个活做到一半，换另一个 AI 接着做

活交接靠文件，不靠聊天记录：

1. 对当前的智能体说：「按 AGENTS.md 第 9 节的格式，把进度写进 `outputs/<主题>-YYYY-MM-DD/README.md`」。
2. 打开另一个智能体，同样从根目录启动，说：「当前项目：xxx。读 `outputs/<主题>-YYYY-MM-DD/README.md`，接着做未完成的部分」。

两个智能体读的是同一份规则、同一份记忆、同一个进度文件，所以接得上。

### 定下来的事，让它一直记住

- 你拍板了一件事、否掉了一个方案、给了一个数据，就说「记一下」。
- 智能体按 `save-memory` 技能列出草稿：写进哪一节、写什么。你确认、修改或删掉，回复「写」，它才写进 `memory/MEMORY.md`。
- 之后换任何一个 AI，开工时都会读到这条。
- 推翻旧结论时，旧的那条会移进「已推翻」，下一个 AI 不会再提已经被否掉的方案。

### 把一个重复的活做成技能

同一类活做到第二、三次，就做成技能：

1. 让当前智能体按你们刚才的做法写一份 `skills/<名字>/SKILL.md`，你审一遍。骨架参考：

   ```markdown
   ---
   name: <名字>
   description: 一句话说明用途和触发时机。
   ---

   # <名字>

   ## 什么时候用
   ## 步骤
   ## 交付什么
   ## 不做
   ```

2. 在 `skills/README.md` 登记一行：用途、触发时机、路径、注意事项。
3. 跑一次自检。下次不管打开哪个智能体，它都会在索引里看到这个技能，用到时读全文再执行。

已经放在 `.claude/skills/` 这类工具专属目录里的技能，挪到 `skills/` 下再登记，所有智能体就都能用了。

### 加一个工具（脚本、上传器、数据同步等）

1. 建 `tools/<名字>/`，放脚本和一份 `README.md`：用途、依赖、入口命令、凭据文件名。
2. 需要密钥时，放在 `tools/<名字>/.env`，已被 `.gitignore` 忽略。规则要求智能体只用 `set -a; . ./.env; set +a` 把它载入环境变量，不打印。
3. 在 `tools/README.md` 登记一行，跑一次自检。
4. 会往外发东西的工具（上传、发送、发布），规则要求智能体先等你确认。

### 加一个项目

建 `projects/<名字>/README.md`，写这个项目做什么、给谁、资料在哪、成品放哪、有什么特殊要求，然后在 `projects/README.md` 登记一行。开工时说「当前项目：<名字>」，智能体就会去读它。

### 改规则

- 规则只改 `AGENTS.md` 一处，不要在子目录、项目 README 或各工具的配置里另写一套。
- 可以让智能体起草修改，你确认后再改；改完跑一次自检。
- `AGENTS.md` 控制在 500 行以内，按需才用的内容拆到技能或项目 README 里。

### 定期维护

- 改过结构（加技能、加工具、加项目、改规则）就跑一次自检。
- `memory/MEMORY.md` 接近 200 行时，让智能体出一版精简草稿，你确认后替换。
- 每次任务结束，智能体按 `AGENTS.md` 第 9 节汇报，并提醒你有没有要记的。

## 安全说明

- 仓库不含任何真实凭据、个人路径或业务数据。
- 让智能体部署前，可以先看一遍 `INSTALL.md`：它只让智能体在你指定的目录里操作，不碰凭据、不改全局配置、不上传任何内容。
- `.gitignore` 默认忽略 `.env`，凭据不要提交进仓库。
- 规则要求智能体只把凭据载入环境变量，不打印、不写进任何文件和回复。
- 自检脚本会扫 `memory/` 和 `identity/` 里的疑似密钥，只报文件和行号，不回显内容。它是正则兜底，查不全，不能代替「不往记忆里写凭据」这条规则。

## 常见问题

### 为什么不用各工具自带的技能目录？

放进 `.claude/skills/` 这类目录，只有那一个工具看得见。放在根目录 `skills/`，所有智能体都能用；代价是技能不会被自动触发，要靠索引匹配后读文件。

### 为什么不在子目录放规则文件分层？

有的智能体会自动读子目录里的规则文件，多一份就多一套规矩，几个 AI 读到的就不一样了。按项目分的约定写在 `projects/<项目>/README.md`，由根规则指过去读。

### 我确实需要按方向分开规则，怎么办？

可以放分线规则文件，但要由根 `AGENTS.md` 在第二层按需加载，并在 `AGENTS.md` 里声明，自检脚本才不会报错：

```markdown
<!-- check:allow-nested -->
- lines/a/AGENTS.md
<!-- /check:allow-nested -->
```

声明的分线规则文件，同样会被部分智能体在进入该子目录时自动读到，所以里面只写这条线自己的规矩，不重复根规则。

### 工作空间放在网络盘上，盘一掉智能体就起不来，怎么办？

在本地建一个跳板目录，只放一个 `CLAUDE.md`，用 `@<网络盘上的绝对路径>/CLAUDE.md` 引入真实规则，并写明「会话开始先检查挂载点」。没挂上时，规则要求智能体停手，并且不往挂载路径下写任何东西：那时那个路径只是本地的一个空目录，写进去的文件，等网络盘重新挂上后会被盖住，看起来就像丢了。

## 它管不了的事

- **读到不等于照做。** 智能体会不会每一步都照规则执行，没有任何系统能百分之百保证。自检和记忆协议能降低漏做的概率，消除不了。
- **各工具自带的记忆还在。** 规则只能要求它们不作依据，删不掉，也管不住它们怎么记。
- **不处理并发写入。** 只约定同一时间只让一个智能体写同一个文件。
- **工具会更新。** 某个工具当前版本读不读 `AGENTS.md`，以你实际用的版本为准，用快速上手第 4 步的复述来确认。
